# CLAUDE.md — このディレクトリ(ebay-dropship-agent/)で作業するときの前提

> **スコープに関する注意:** これはリポジトリルートの `CLAUDE.md`(Next.js サロン予約 SaaS 向け)とは無関係の、
> 独立したサブプロジェクトです。このディレクトリ配下で作業するときのみ、以下を適用してください。
> ルートの `CLAUDE.md` / `AGENTS.md`(Next.js 関連)は、このディレクトリの実装には関係ありません。

このディレクトリは **eBay 無在庫ドロップシッピング(卸直送)を PDCA で自動化する、承認付き自動実行のエージェント** を実装するためのものです。

## 最初に読むファイル(入口)

1. `PROMPT.md` … システム全体の設計図(アーキテクチャ / PDCAループ / データモデル / eBay API方針 / 開発フェーズ)。**これが本体・入口。**
2. `AGENT_PROMPTS.md` … 各エージェント(リサーチ / 出品ドラフト / 価格・次アクション / 受注処理)のプロンプトと共通の提案エンベロープ。
3. `compliance.md` … eBay の無在庫・ドロップシッピング規約と API・レート制限の要点。

作業を始める前に、この3つを必ず全部読むこと。3ファイルは相互に参照し合っているので、部分的な理解で着手しないでください。

## 進め方(この順序を守る)

1. 3ファイルを読む。
2. `PROMPT.md` 第11章「まず最初にやること」に従い、着手前の確認質問を最大5個する。回答を得るまで実装を始めない。
   (このプロジェクトでは配置場所・サプライヤー連携方式・承認UI・PDCAサイクル頻度は確認済み。`DECISIONS.md` 参照。)
3. 回答が出たら **第0フェーズから順に**、フェーズごとに「実装 → テスト → 何をしたかの説明 → 次フェーズの確認」を繰り返す。フェーズを飛ばさない。
4. 各フェーズの最後にテストを通し、`DECISIONS.md` に設計判断を残す。

## 常に最優先するルール(機能より上位)

- **仕入れは卸・サプライヤーからの直送のみ。** 小売サイト(Amazon 等)から仕入れて転送する小売アービトラージは扱わない。該当する設計・入力が出たら止めて警告する。
- **副作用のある操作(出品公開 / 価格変更 / 出品取り下げ / サプライヤー発注)は必ず「提案 → 人間の承認 → 実行」の3段**にする。承認なしに外部へ副作用を出さない。
- **公式 eBay Sell API のみ**を使う(スクレイピング等は使わない)。レート制限を尊重する。
- **利益ガード**:純利益が目標を下回る値下げ・発注は自動提案しない。
- 各エージェントの出力は `AGENT_PROMPTS.md` の**共通エンベロープ(proposal_type / requires_human_approval / rationale 等)**に必ず揃える。
- 実出品・実発注の前に必ず **Sandbox** で通す。トークンは `.env`(コミット禁止)で管理する。

迷ったら安全側(実行しない / `hold` にする)に倒し、その判断を `rationale` と `DECISIONS.md` に残すこと。
